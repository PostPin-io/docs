# PostPin Docs

Docusaurus site for PostPin (https://docs.postpin.io), deployed to GitHub Pages by
`.github/workflows/deploy.yml` on every push to `main`. Content is English.

The docs describe one specific commit of the main repo, `PostPin-io/postpin@main`. That commit
lives in `source.json`. Never document features that only exist on feature branches.

## Layout

- `docs/guide/`: web app user guide
- `docs/plugins/`: DaVinci Resolve plugin and PostPin Desktop (Pro Tools)
- `docs/self-hosting/`: self-hosting guide. It used to be `docs/self-hosting.md` in the main
  repo; this site is now its home.
- `docs/api/index.md`: hand-written API intro. `docs/api/reference/` is generated from
  `openapi/swagger.json` by `docusaurus gen-api-docs all` (runs automatically before
  `start`/`build`, gitignored).
- `docs/downloads.md`: download page.
- `openapi/swagger.json`: tsoa spec from the source commit, enriched by `scripts/sync-openapi.mjs`
  (tags, server URL).
- `static/img/screenshots/`: generated by `pnpm screenshots`. Do not edit by hand. Web app shots
  come in a light (`<name>.png`) and a dark (`<name>-dark.png`) variant, plus `web/manifest.json`
  with each shot's page URL and whether it's a whole page or a cutout.
- Web app screenshots go into docs with `<Screenshot name="review" alt="…" />`
  (`src/components/Screenshot`, available in every doc without an import). It picks the variant
  for the docs' theme and frames whole pages in a browser window. Plugin screenshots are plain
  Markdown images (the plugins are always dark).
- `screenshots/`: Playwright script, demo seed and the throwaway backing services
  (`compose.yml`, own project name and ports, nothing persisted).

## Updating the docs to a newer PostPin commit

1. Read `source.json` and set `OLD` to its `commit`. Fetch the main repo and set
   `NEW=$(git rev-parse origin/main)`.
2. Read the change list: `git log --oneline $OLD..$NEW` and `git diff --stat $OLD..$NEW`, then the
   full diff of everything user-facing:
   - `packages/postpin/src/routes/**` and `packages/postpin/src/lib/components/**`: web UI, labels, flows
   - `packages/postpin/src/api/**`: REST API
   - `packages/plugin-*/**`, `packages/desktop/**`: plugins
   - `deploy/**`, `.env.example`, `packages/*/Dockerfile`, `docker/**`, `packages/shared/src/env*`: self-hosting
   - `.github/workflows/release.yml`: release assets and download links
3. Update every page affected by the diff. Check UI labels against the source; the docs quote them.
4. Create a detached worktree of the main repo at `$NEW` and run
   `pnpm screenshots <path-to-worktree>`. It needs Docker, and `PIXABAY_API_KEY` if the clips in
   `screenshots/clips.json` aren't cached yet (ask the user for the key, never commit it). If the
   diff changes the worker's ffmpeg calls, check that `screenshots/bin/ffmpeg` still applies. Afterwards, look at every changed PNG
   (`git status static/img/screenshots`) to check that it still shows what the text says.
5. `node scripts/sync-openapi.mjs <worktree>`. The screenshot run has already generated the spec.
6. `pnpm build` must pass (broken links throw).
7. Set `commit`, `commitSubject` and `syncedAt` in `source.json` to the new state and commit with
   `docs: sync to postpin@<short-sha>`. Use one commit per sync, so `git log source.json` shows the
   history.
